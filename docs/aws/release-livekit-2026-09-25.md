## Hosted transport

The existing EC2 host and public TCP443 permission are reused. HAProxy routes app/RTC TLS to private Caddy8443, preserving actual visitor addresses with required PROXYv2. The RTC hostname exposes only signaling/validation routes; the app's existing operator authentication stays intact. The TURN hostname terminates trusted TLS443 and forwards authenticated TURN to the colocated private SFU. Browsers must select relay ICE; TURN peers are restricted to that SFU's private address. No security-group changes, new instance, cloud account or external TURN service.

Dedicated unprivileged LiveKit Server1.13.7, SDK pins and [binary provenance](../qa/aws-livekit-release-2026-09-25/binary-provenance.json) are recorded. Runtime origin, grant, message, rate and room limits apply; **two simultaneous LiveKit rooms** are supported by admission policy on this small host. This is not broad concurrency/load acceptance. Default local launcher at [localhost8910](http://127.0.0.1:8910/) preserves the selected workspace and uses LiveKit without a flag.

SFU and HAProxy are enabled across restarts. Caddy renews certificates through HTTP01; a six-hour private certificate-sync timer validates hostname, key and lifetime, atomically updates the TURN certificate and verifies the trusted served leaf. Failed updates restore the prior certificate. Timer/service activation succeeded. Pinned TURN's300-second credential limit applies to new allocation, not a five-minute visit limit; existing allocation refresh remains authenticated.
