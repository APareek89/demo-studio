# Operational FMEA: hosted LiveKit transport

Scope: the transport renderer, pinned SFU deployment, Caddy/HAProxy edge, private certificate renewal, bounded activation/rollback and isolated hosted mock fixture in this directory. The application review and source-release helpers have their own review. Product context is PRD.MD's default LiveKit paragraph: preserve the existing demo/voice/evidence/session ownership; hosted443 authenticated relay, exact origins, short room-scoped tokens, two rooms and visible failure. Current EC2 has approximately913MiBRAM,526MiBavailable before this release,2GiBswap and7.5GBfree disk. Capacity numbers are a preflight observation, not a load-test guarantee.

The whole customer flow was traced: public gallery loads → discovery chooses LiveKit → exact public token route → WSSsignalling → browser relays through443 → same-host SFU worker → existing answer/PCM controls → renewal/reconnect → shutdown. The competing deployment choice (public UDP/TCPICE) was rejected because current IAM cannot safely reverse SG modifications; the chosen path leaves SGs unchanged.

## Findings and dispositions

1. **Rollback abandoned after a timed-out stop** would leave the public edge unavailable. S7×O3×D5=105,P1 before fix. `bootstrap.rollback` now catches each timeout/OSfailure independently, attempts every stop/disable, restores Caddy and verifies original trusted publicHTTPS. Root and the independent reviewer confirmed the patch. Post-fix detection is through staged error handling plus explicit HTTPS recovery; no claim of a production outage drill.
2. **Partial release units enabled after rollback** could break the original edge after reboot. S7×O3×D6=126,P1 before fix. Rollback now disables the three newly owned units as well as stopping them; original inactive HAProxy config is restored when one existed. App drop-ins and production data are deliberately outside transport rollback.
3. **Renewal killed after PEM replacement** could strand TLS on a broken replacement. S6×O3×D5=90,P2 before fix. Every subprocess is bounded, TLS retries fit the120sunit timeout, SIGTERM enters restoration, and atomic PEM replacement is inside the protected try block. The served trusted leaf is checked after reload; a failed check restores the oldPEM and attempts a reload. Root's actual renewal acceptance remains required.
4. **Forwarded address spoofing / token leakage through proxy errors** would defeat app rate ownership or expose credentials. S8×O3×D6=144,P1 before mitigation. Only loopback accepts PROXYv2, Caddy requires it, generated config does not trust inbound XFF, and error logs filter URI/Authorization/Cookie. `edge_contract.py` sends from127.0.0.2 with spoofed XFF/scheme, exercises TURN PROXYv2 and forces a query-token-bearing upstream failure. Actual contract must pass before edge activation.
5. **Private relay advertised without real external browser proof** could produce a functioning UI with silent media. S6×O5×D4=120,P1 release gate. Root must run the native browser from Mac through publicWSS/TURN while only the mock UI travels overSSH. Selected ICE must be relay and show PCM/control bytes. Strict parser/HTTPS tests alone do not resolve this gate.
6. **OneGiBhost overloaded by rooms/QA** could interrupt all feedback visitors. S6×O4×D4=96,P2 residual. Runtime admits two rooms; SFU caps256MiB/oneCPU, optional QA app384MiB/oneCPU, TURN allocations6perparticipant and relay101ports. Resource state is checked during hostedQA; the temporary QA app is removed afterwards. This release does not promise large concurrency or introduce a billed larger instance.

No remaining confirmed P0 code defect was identified in this scoped review. Findings1–4 were addressed in the tools; hosted transport acceptance is a required release gate, not a claim already satisfied. Synthetic media does not establish physical microphone/noise recognition quality, prolonged network-change recovery or hour-long acoustic performance.

Actual verification at this checkpoint: existing Caddy boundary153/153 and new real TLS/PROXY edge41/41 on isolated AWS fixtures; recovery fault injection10/10 locally. The latter injects a real SIGTERM within the protected certificate-activation phase and a timed-out stop/failed old-HAProxy-config copy, proving subsequent Caddy restoration; it also forces a wrong served certificate and verifies oldPEM recovery/reload. The edge fixture caught Caddy directive ordering that would have made every RTC route404; exclusive matched/fallback handles fixed it before activation. Strict SFU parsing also surfaced upstream's scalarUDPport `%s` formatting bug; the pinned output assertion was narrowed to that known representation, not removed. No paid call or active application mutation is involved in these tests.

The first attempted private-SFU activation then failed before the public listener change, and rollback restored the original edge. Read-only diagnosis confirmed the private operator umask had reduced mkdir0755/0750 to0700: the service account could neither traverse its binary path nor read its configuration. The helper now explicitly chmods only those reviewed directories and tests executable/read access as the real service account during stage. Two regression checks exercise umask077 and verify secret files remain0600. Root owns repair/retry of the already staged directory modes. This is an observed staging incident, not an unverified hypothesis; the sanitized failure signals were Permission denied/Failed at EXEC. Production demo data remained untouched.

The next bounded private startup exposed a second service-profile problem before public edge cutover: Go's interface enumeration failed with `netlinkrib: address family not supported by protocol`. The service address-family allowlist now includesAF_NETLINK alongside IPv4/IPv6/Unix. The service remains a dedicated unprivileged user without CAP_NET_ADMIN, so network discovery does not grant route administration. The health window is bounded at30seconds. Strict YAML parsing and fixture proxies did not exercise the actual SFU systemd sandbox; the real private service startup is therefore an explicit separate prerequisite for public activation. The second automatic rollback again restored the prior public edge; root preserves each attempt's receipt independently.

After these corrections, root reported private startup and trusted TURN/app edge activation passed, with the original application still active and private RTC routes denied. The SFU unit uses `Restart=always`: pinned upstream main prints certain fatal errors but returns exit0, which `on-failure` would not recover. An explicit systemctl stop still prevents restart. This unit-policy update requires daemon-reload but no test-interrupting SFU restart; root coordinates it with hosted acceptance.
