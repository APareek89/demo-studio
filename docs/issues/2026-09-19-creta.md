## CR07 — Gemini's legacy schema converter rejected flexible fields

- Where: third real Read, first fact-extraction call.
- Expected: the extraction schema reaches the configured model; valid structured output returns with scoped facts.
- Actual: the SDK rejected `additionalProperties` locally in six milliseconds. Anthropic had insufficient credit and the Runware fallback timed out after 120 seconds. No facts were published.
- Cause: `response_schema` uses a legacy schema converter that rejects dictionary properties. The new evidence scope and delivery metadata contain dictionaries. Readiness's simpler schema did not exercise this shape.
- Fix: send the model's JSON Schema through `response_json_schema`, preserving constraints and validating the response with Pydantic. Separate build routing now tries Gemini first for text-only calls; explicit runtime routing and media calls keep their contracts.
- Status: SDK wire regression 4/4; a real small `FactsOut` call returned a valid fact and scope. Full extraction replay pending. Official API reference: https://ai.google.dev/gemini-api/docs/generate-content/structured-output.
