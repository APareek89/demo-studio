# Preserved failures and acceptance corrections

The baseline is not rewritten: the unchanged `eacbb57` browser contract was 85/87. Its two failures were the 11.5px phone evidence type and a cue fixture that expected the third compact card to scroll even though that layout intentionally wraps it. The final middle-only style raises evidence type to 12px; the overflow fixture now uses four cards to test actual scrolling. Full original baseline evidence remains in `baseline/player-browser-baseline.json`.

The new gallery checks were developed against actual `mountPlayer`. Early harness runs are diagnostic evidence, not application acceptance:

- Initial phone document-width assertions caught the existing closed conversation drawer at x=390–780, not an escaping gallery. `diagnostics/overflow.json` records the offender. The final checks measure the central gallery and its caption bounds; top, dock and control geometry are separately compared with the unchanged baseline.
- The first CRETA route loop ran before opening narration had created the browse route. A later run attempted a nonexistent progress button for an opening slide. The completed harness explicitly consumes and checks opening clips, requires at least twelve route slides, and remounts the original published bundle independently for desktop and phone. The early synthetic-only 56/56 result did not establish CRETA acceptance.
- The first real-image server resolved media files through macOS `/private/tmp` but compared that path with the unresolved `/tmp` fixture root, incorrectly returning 404. This was a test server bug. The root is now resolved before containment checks. Final acceptance requires decoded image dimensions and zero failing source-image HTTP responses; the approved bundle and source media were not modified.
- Source inspection during that work exposed an actual simultaneous-image case: CRETA slides `sl03`, `sl04` and `sl06` have two photos and labels sharing `from_line: 0`. The implementation was corrected to retain both pictures and all eligible tags. Final checks exercise every tag's exact source-image ownership without replaying audio.

The first full final gallery run passed 312/312 and the accompanying player contract was 86/87. Its failure was `Personalized boot evidence reuses its complete reviewed label and image, not the current cabin` with `Fixture did not reach its personalized slide`: the fixture checked after microtasks only while the newly asynchronous opening image was still decoding. All evidence/scope assertions remain unchanged; the helper now waits for real browser readiness. The first retry also reported 86/87 with `Illegal invocation`, because the saved browser timer was invoked with the helper object as receiver. Calling that original timer with `window` fixed the harness binding. The final unchanged product source passes **87/87**, recorded in `player-browser-current.json` and `logs/player_browser_final.log`. The original full-run 86/87 count remains visible in `logs/gallery_browser.log`; intermediate 86/87 JSON files were superseded by the final result, so their exact observed errors are preserved here.

After the final local caption-scroll repair, twelve focused browser checks pass: preparation-time tag/inset clicks cannot cancel the original line, controls unlock after readiness, the selected caption scrolls into view, scrolling redraws or hides the corresponding pointer, and audio, route, top navigation and dock geometry remain unchanged. These are in `prepare-click-browser.json`; they supplement the 312-case full gallery run rather than pretending that run included checks added afterward.

All checks used muted isolated browser processes and local fakes or existing recorded assets, with external requests blocked. They establish UI/ownership behavior, not acoustic or production-model quality.
