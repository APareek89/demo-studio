## Provider contract used

Google's [Python SDK system-instruction documentation](https://googleapis.github.io/python-genai/#system-instructions-and-other-configs) and [Generate Content reference](https://ai.google.dev/gemini-api/docs/generate-content/text-generation) explicitly put policy in `GenerateContentConfig.system_instruction` and user input in `contents`. The fix uses that supported request shape with the original exact strings. It does not replace history formatting, add a model call or relax downstream validation.

Google's current [Gemini3.8 model reference](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash) supports LOW/MEDIUM/HIGH and explicitly rejects MINIMAL. Its [thinking guide](https://ai.google.dev/gemini-api/docs/thinking) lists the3.8 default as medium; the older generic Gemini3 guide's high default must not be attributed to this observed call. The [developer guide](https://ai.google.dev/gemini-api/docs/gemini-3) treats levels as relative reasoning allowances, not strict token guarantees. The fix therefore requests LOW only in the existing exact3.8 build path, preserving JSON validation, output budgets, retries and billed thought-token accounting.

Sarvam's [REST conversion reference](https://docs.sarvam.ai/api-reference/text-to-speech/convert), [stream reference](https://docs.sarvam.ai/api-reference/text-to-speech/stream) and [best-practice guide](https://docs.sarvam.ai/api/api-guides-tutorials/text-to-speech/best-practices) document temperature as expressive variation, with default0.6; the application deliberately narrows it to0.5–0.8. The stream's documented range is narrower than REST, so direct adapters share0.01–1.0 validation. Bulbul v3 does not expose the requested precise pitch/loudness controls; the [model guide](https://docs.sarvam.ai/api/getting-started/models/bulbul) does not support SSML. Optional expression therefore requests variation, never guaranteed chosen-word emphasis. Existing voice identity, source text and selected duration remain the contract.
